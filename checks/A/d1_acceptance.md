## 6. 发现（均不阻断合并）

### F1（中）锚包选择只用 `rho`，极性翻转让锚包取决于包顺序
- **复现**：4 个包，第 0 包取 `-base`、其余 `base`。`rho` 对极性翻转不敏感（全为 1），锚包评分并列，按"取小序号"选中翻转包；随后 3 个正常包因 `|phi|=π` 被 `inter_packet_phase_offset` 拒绝，`n_accepted=1`，输出为翻转包。把顺序改为 `[base, -base, base, base]` 则接受 3 个正常包。
- **影响**：默认数据未见极性翻转，输出仍是一个真实包（不伪造），但"锚包=最有代表性"的意图在并列时失效，且丢包数依赖输入顺序。
- **建议**（非本轮必须）：锚包评分加入相位一致性（例如"以候选为锚时能通过 `phi/gain` 的同伴数"），或先按 `|phi|` 聚类取最大簇；契约 §3.2 补一句并列规则的已知局限。**责任**：dsh（实现）/ codex（是否要求本轮修）。

### F2（低）非参考通道出现 NaN 时静默污染 `signals_folded`
- **复现**：`packets[0,5,:]=NaN`（其余正常）。`gamma` 把该通道排除出中位数，但折叠仍把它纳入均值，输出含 NaN 且不报错。
- **影响**：契约 §4.1/§7 要求输出全有限；但 D0 输入是 `int16`，实际数据路径不可达（NaN 只可能来自人工构造的 `GroupData`）。
- **建议**：返回前加 `np.isfinite(signals).all()` 断言，或按 `gamma_active` 剔除通道并记录原因码。

### F3（低）包间门控只覆盖参考通道，不能给全阵"≤0.5% 相干损失"背书
- **事实**（本报告独立统计，1 GHz 单 bin、段 0）：data1 参考通道 28 包间漂移 ≤1.70°；但其余接收通道最大 **13.13°（ch61）**、次之 ch22 5.47°；中位 1.69°。按 2 包平均估算 ch61 的相干损失约 `1-cos(6.6°)≈0.7%`。
- **影响**：契约 §2.5 的"残余相位散布 ≤0.1 rad、损失 ≤0.5%"只在 ch28 上被门控保证；其他通道未被约束（契约 O-D1-02 已提到行板级差异，但未量化）。不改变 data1 通过结论（损失仍远小于后续测距误差预算），但 E0 前应把该量列入逐组预检。
- **建议**：`channel_summary` 增加"包间相位漂移（每通道）"诊断列，或在契约中把 ≤0.5% 限定为"参考通道"。

### F4（说明）字节级 hash 复跑依赖 numpy 版本
- 作者提交的诊断 JSON SHA256 `2BABB0BD…` 只在其环境（numpy 2.1.3）成立；本机 numpy 1.26.4 复跑得到 `AA4C2459…`，但数值最大相对差 **8.3e-15**、结构与判定完全相同。**语义可复现，字节级可复现需固定依赖版本**（建议在 E0 登记中锁定 Python/numpy 版本）。

### F5（说明）`--diagnose` 在全拒时退出码仍为 0
- 代码路径 `diagnose()` 返回 `status="all_rejected"`，`main()` 恒返回 0（与 D0 `--inspect` 的已知后修项同类）。JSON 有明确 `status`，不影响库调用方；如 CI 依赖退出码需注意。

### 其他小项
- M1：`gamma_median_rx` / `n_rx_below_gamma` 的统计池排除了 `gamma` 未定义（零能量）的通道；契约写"有效接收通道的中位数"，未明确该排除，属措辞可补，不影响 data1（全通道有效）。
