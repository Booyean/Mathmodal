## 3. 独立方法

1. 按 `附件1-数据读取函数/get_data_iq.m` 重写解析器：4 字节对齐搜索 `magic=963072`，`total_len` 语义、`type!=102` 跳过 `total_len-4`、`freq/sync/num/len`、`num*len/2` 个 `<i2`、`reshape(8, [])`，全部独立实现；**期望值不来自 `a_dat_reader.py`**。
2. 扫描全部 881 个文件，逐文件计算 SHA256、包数、`sync` 序列、`num/len/freq`、端点（`int32` 升位后的 `==32767` / `==-32768` / `==0`）。
3. 与 R0 清单 `recon/manifests/a_dat_manifest.csv` 逐行对账（881 行）：SHA256、包数/`sync_ids`、三个端点计数。
4. 与作者读取器对照：组发现集合、真实组数组（`data1-42cm` 3 包 × 64 通道 × 16000 点逐点）、元数据常量、`rx_mask`、坐标、`--max-packets` 语义。
5. 用自造 `.dat`（8 行 × 16 000 点 int16，按协议写头）覆盖 D0-2/D0-3 与异常分支：文件内重复 `sync`、整行无契约形状包、截断且 `num*len/2` 非 8 倍数、交集为空、非数据包/前导空隙/尾部残留、`total_len` 不符、非法文件名。

## 5. 非阻断发现（建议合并时一并处理）

1. **契约 §3 对“整组无可用行”的措辞与实现不一致**（建议改文档，不改行为）。
   契约写：“某行文件 0 字节 …… `--allow-incomplete` 时该行通道 `channel_valid=False`”。而 `2026-11-12-22-50-31_16000` 只有 1 个 0 字节行、其余 7 行缺失，`require_all_rows=False` 时实现仍抛 `IncompleteGroupError: 没有任何可用行文件`（`load_group` 在 `usable_rows` 为空时无条件抛错）。这是**安全**的（没有用 0 伪造任何数据），但契约应补一句：“当整组无任何可用行时，即使 `--allow-incomplete` 也拒绝返回，`--inspect` 输出 `error` 记录”。建议在 `data_contract.md` §3 增一行说明。
2. **`--max-packets` 未校验负值**：`--max-packets -1` 会静默返回 `P=len-1` 的包并登记 `max_packets_applied=-1`。建议 CLI/`load_group` 拒绝 `<0`（或 `<1`），避免脚本误用。不影响默认路径。
3. **`--inspect` 在 `IncompleteGroupError` 时进程退出码为 0**（stdout 输出 `error` JSON）。若下游脚本以退出码判失败会漏检；建议改为非 0（如 3），或在契约里明确“以 JSON 的 `error` 字段判定”。不影响数据正确性。
4. **0 字节文件在 R0 清单中 `sha256` 为空**，而 D0 `meta` 存空字节的 SHA256（`e3b0c442…`）。两者语义一致但形式不同，建议在契约 §1.1 注明“空文件清单 SHA 为空，读取器按空字节流计算”，便于逐项对账。
